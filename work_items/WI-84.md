## Overview
Refactor external scene handling to implement "resolve early, use late" pattern. Currently, external scene resource metadata is resolved lazily during rendering. This work item moves resolution to parse time while keeping actual scene loading lazy, improving performance and reducing complexity in the rendering path.

## Current Architecture (Lazy Resolution)

**Problem**: NodeLifecycleManager must resolve external resource metadata during rendering:
```typescript
// Current flow (Lazy Resolution)
// 1. Parse main scene
// 2. Start rendering nodes
// 3. Encounter instance node → look up resource metadata
// 4. Resolve resource path from ID
// 5. Load external scene
// 6. Add external scene nodes
```

**Issues with Current Approach**:
- Rendering code must know about ResourceRegistry
- Metadata resolution happens during node creation (coupling)
- External scenes loaded at L2+ couldn't resolve their dependencies (Bug #2)
- Resolution logic duplicated across rendering code

## Target Architecture (Resolve Early, Use Late)

**Solution**: Resolve all resource metadata during parsing, use metadata during rendering:
```typescript
// Target flow (Resolve Early, Use Late)
// 1. Parse main scene
// 2. Resolve ALL instance references → store metadata in TscnNode
// 3. Start rendering nodes
// 4. Encounter instance node → metadata already attached
// 5. Load external scene using pre-resolved metadata
// 6. Add external scene nodes
```

**Benefits**:
- NodeLifecycleManager simplified (no ResourceRegistry dependency)
- All metadata resolution happens in one place (SceneManager.loadScene)
- Clearer separation of concerns (parsing vs rendering)
- Easier to reason about external scene dependencies
- Enables future features (dependency graph analysis, prefetching)

### Commit 4: Add resolveInstanceReferences method
**File**: `packages/textscene-core/src/core/SceneManager.ts`

**New method**:
```typescript
/**
 * Resolve all instance references in a scene to metadata
 * Sets userData.instanceMetadata on instance nodes
 */
private resolveInstanceReferences(scene: TscnScene): void {
  if (!this.resourceRegistry) {
    logger.warn('[SceneManager] Cannot resolve instances - ResourceRegistry not set');
    return;
  }

  // Recursively resolve instances in all nodes
  for (const node of scene.nodes) {
    this.resolveNodeInstanceReferences(node);
  }
}

private resolveNodeInstanceReferences(node: TscnNode): void {
  // Check if this is an instance node
  const instanceId = node.properties.instance as string | undefined;
  if (instanceId) {
    // Extract resource ID: "ExtResource('1_scene')" → "1_scene"
    const match = instanceId.match(/ExtResource\(['"]([^'"]+)['"]\)/);
    if (match) {
      const resourceId = match[1];
      const metadata = this.resourceRegistry!.getMetadata(resourceId);

      if (metadata) {
        // Store resolved metadata on node for later use
        node.userData = node.userData || {};
        node.userData.instanceMetadata = {
          resourceId,
          scenePath: metadata.path,
          resourceType: metadata.type
        };
        logger.info(
          `[SceneManager] Resolved instance: ${node.name} → ${metadata.path}`
        );
      } else {
        logger.warn(
          `[SceneManager] Instance resource not found: ${resourceId} (node: ${node.name})`
        );
      }
    }
  }

  // Recurse to children
  if (node.children) {
    for (const child of node.children) {
      this.resolveNodeInstanceReferences(child);
    }
  }
}
```

**Testing**:

```

### Commit 6: Use pre-resolved metadata in NodeLifecycleManager
**File**: `packages/textscene-core/src/core/NodeLifecycleManager.ts` (lines ~180-220)

**Current code** (lazy resolution):
```typescript
// Check if this is an instance node
const instanceId = node.properties.instance as string | undefined;
if (instanceId) {
  const match = instanceId.match(/ExtResource\(['"]([^'"]+)['"]\)/);
  if (match) {
    const resourceId = match[1];
    const metadata = scene.resourceRegistry?.getMetadata(resourceId);
    if (metadata?.path) {
      await this.sceneManager!.addScene(nodePath, metadata.path);
    }
  }
}
```

**New code** (use pre-resolved metadata):
```typescript
// Check if this is an instance node with pre-resolved metadata
const instanceMetadata = node.userData?.instanceMetadata;
if (instanceMetadata?.scenePath) {
  // Use pre-resolved metadata - no registry lookup needed
  await this.sceneManager!.addScene(nodePath, instanceMetadata.scenePath);
  logger.info(`[NodeLifecycle] Using pre-resolved instance: ${nodePath} → ${instanceMetadata.scenePath}`);
} else if (node.properties.instance) {
  // Fallback: instance property exists but metadata wasn't resolved
  logger.warn(
    `[NodeLifecycle] Instance node missing pre-resolved metadata: ${nodePath}. ` +
    `This may indicate the scene wasn't loaded through SceneManager.loadScene()`
  );
}
```

**Benefits**:
- No ResourceRegistry dependency in NodeLifecycleManager
- Resolution happens once during parsing
- Clearer code - metadata is already available
- Better error messages (can detect missing resolution)

### Commit 8: Add warning for duplicate resource IDs
**File**: `packages/textscene-core/src/core/SceneManager.ts`

**Update loadScene() resource registration**:
```typescript
// Register external scene's own resources in shared registry
for (const extResource of scene.externalResources) {
  // ✅ NEW: Check for duplicate IDs
  const existing = this.resourceRegistry.getMetadata(extResource.id);
  if (existing && existing.path !== extResource.path) {
    logger.warn(
      `[SceneManager] Duplicate resource ID detected!\n` +
      `  ID: ${extResource.id}\n` +
      `  Existing: ${existing.path}\n` +
      `  New: ${extResource.path}\n` +
      `  This may cause incorrect resource resolution.`
    );
  }

  this.resourceRegistry.register(extResource);
  logger.info(
    `[SceneManager] Registered resource from ${scenePath}: ${extResource.id} → ${extResource.path}`
  );
}
```

**Why this matters**:
- Godot generates resource IDs like `1_mesh`, `2_material`
- Different scenes might use the same IDs
- Duplicate IDs can cause Scene A's resource to resolve to Scene B's file
- Warning helps developers identify conflicts

**Testing**:

## External Scene Resolution: "Resolve Early, Use Late"

The renderer uses a "resolve early, use late" pattern for external scene handling:

1. **Parse Time (Early)**:
   - `SceneManager.loadScene()` parses scene content
   - Registers external resources in shared ResourceRegistry
   - Calls `resolveInstanceReferences()` to resolve ALL instance metadata
   - Stores metadata in `node.userData.instanceMetadata`

2. **Render Time (Late)**:
   - `NodeLifecycleManager.addNode()` encounters instance node
   - Uses pre-resolved `instanceMetadata` (no registry lookup needed)
   - Calls `SceneManager.addScene()` with resolved path
   - External scene is loaded and rendered

**Benefits**:
- Clear separation: parsing resolves metadata, rendering uses it
- NodeLifecycleManager doesn't need ResourceRegistry dependency
- All resolution happens in one place (easier to debug)
- Enables dependency analysis and prefetching

**Example**:
```typescript
// After loadScene(), instance nodes have metadata attached:
{
  name: "EnemyInstance",
  type: "Node3D",
  properties: { instance: "ExtResource('1_enemy')" },
  userData: {
    instanceMetadata: {
      resourceId: "1_enemy",
      scenePath: "res://enemies/goblin.tscn",
      resourceType: "PackedScene"
    }
  }
}
```
```

## Performance Considerations

**Resolution cost**: O(n) where n = total nodes in scene (depth-first traversal)
**When it happens**: Once during `loadScene()`, not during rendering
**Memory overhead**: Small - just metadata objects in `userData`
**Net benefit**: Reduces rendering complexity, enables future optimizations
