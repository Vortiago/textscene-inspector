# WI-63: Comprehensive Texture Enable Flags (StandardMaterial3D)

**Status**: Not Started
**Priority**: Medium
**Complexity**: Moderate
**Impact**: Complete Godot material feature parity for all texture types

## Overview

### Problem Statement

After implementing `normal_enabled` (WI-59) and `emission_enabled` (WI-62), we have an **incomplete pattern**:

**Currently Implemented**:
- ✅ `normal_enabled` - Controls normal map application (WI-59)
- ✅ `emission_enabled` - Controls emission map application (WI-62)

**Still Missing** (Applied unconditionally):
- ❌ `metallic_texture` - No `metallic_texture_enabled` or similar flag checked
- ❌ `roughness_texture` - No `roughness_texture_enabled` or similar flag checked
- ❌ `ao_texture` - No `ao_texture_enabled` or similar flag checked
- ❌ Other potential features: heightmap, rim, clearcoat, anisotropy, detail, etc.

**Risk**: Users loading Godot TSCN files may see **incorrect rendering** if textures are applied when features are disabled.

### Godot's Feature System

Godot's `BaseMaterial3D` uses a `Feature` enum pattern (source: `godot/scene/resources/material.h`):

```cpp
enum Feature {
  FEATURE_EMISSION,
  FEATURE_NORMAL_MAPPING,
  FEATURE_RIM,
  FEATURE_CLEARCOAT,
  FEATURE_ANISOTROPY,
  FEATURE_AMBIENT_OCCLUSION,
  FEATURE_HEIGHT_MAPPING,
  FEATURE_SUBSURFACE_SCATTERING,
  FEATURE_SUBSURFACE_TRANSMITTANCE,
  FEATURE_BACKLIGHT,
  FEATURE_REFRACTION,
  FEATURE_DETAIL,
  FEATURE_BENT_NORMAL_MAPPING,
  FEATURE_MAX
};

void set_feature(Feature p_feature, bool p_enabled);
bool get_feature(Feature p_feature) const;
```

**Question**: How are these features saved in TSCN files? Do they map to properties like:
- `emission_enabled` (confirmed ✅)
- `normal_enabled` (confirmed ✅)
- `ao_enabled` or `ambient_occlusion_enabled`?
- `heightmap_enabled`?
- `rim_enabled`?
- etc.

**This work item includes research to answer these questions.**

## Research Phase

### 1. Analyze Real Godot TSCN Files

**Task**: Create test materials in Godot 4.x with each feature enabled/disabled and examine resulting TSCN:

```
1. Create StandardMaterial3D in Godot
2. Enable each feature (Emission, AO, Heightmap, Rim, etc.)
3. Save scene as .tscn
4. Grep for "*_enabled" properties
5. Document property names
```

**Expected Findings**: Discover which features save as `*_enabled` properties vs. other patterns.

### 2. Search ld-58 Corpus

**Task**: Scan ld-58 game jam project TSCN files for undocumented enable flags:

```bash
grep -r "enabled" ld-58/**/*.tscn | grep -v "shadow_enabled" | sort -u
```

**Goal**: Find real-world usage of features beyond emission/normal.

### 3. Consult Godot Documentation

**Resources**:
- [BaseMaterial3D Class Reference](https://docs.godotengine.org/en/stable/classes/class_basematerial3d.html) - Full property list
- [StandardMaterial3D Tutorial](https://docs.godotengine.org/en/stable/tutorials/3d/standard_material_3d.html) - Feature explanations
- Context7 MCP: `websites/godotengine_en_stable` - Up-to-date API docs

**Goal**: Confirm official property names for each feature flag.

### 4. Priority Assessment

**After research**, categorize features by priority:

**High Priority** (Common in real scenes):
- AO (ambient occlusion) - Likely used in PBR workflows
- Heightmap/parallax - Depth effect enhancement

**Medium Priority** (Specialized use cases):
- Rim lighting - Edge highlighting effect
- Clearcoat - Glossy finish layer
- Anisotropy - Directional reflection (brushed metal)

**Low Priority** (Rare/advanced):
- Subsurface scattering/transmittance - Skin/wax materials
- Backlight - Translucency
- Refraction - Glass materials
- Detail maps - Texture layering
- Bent normal mapping - Advanced lighting

### 3. Update Renderer

```typescript
// BEFORE (incorrect):
if (properties.ao_texture) {
  materialOptions.aoMap = properties.ao_texture;

// AFTER (correct):

  materialOptions.aoMap = properties.ao_texture;
}
```
