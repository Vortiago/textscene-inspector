# WI-50: VSCode Outline Provider Integration

## Overview

Implement a lightweight `DocumentSymbolProvider` for .tscn files to integrate with VS Code's native Outline view, breadcrumbs, and "Go to Symbol" (Ctrl+Shift+O) navigation. This feature **complements** (not replaces) the existing webview tree viewer, providing native VS Code navigation without duplicating code or violating the project's feature parity principle with the web app.

**Key Benefits:**
- ✅ Native VS Code Outline panel integration
- ✅ Breadcrumbs navigation in editor header
- ✅ Quick symbol navigation (Ctrl+Shift+O)
- ✅ Minimal implementation (~100 lines)
- ✅ Zero code duplication with webview tree
- ✅ Maintains feature parity (web app keeps full webview tree)
- ✅ Uses existing `parseTscn()` parser from `@textscene/renderer`

## Implementation Requirements

From TODO.md Phase 6: VS Code Extension UX Improvements:

- Parse TSCN files using existing `parseTscn()` from `@textscene/renderer`
- Map TSCN node hierarchy to VS Code `DocumentSymbol` objects
- Assign appropriate `SymbolKind` for different node types (MeshInstance3D → Class, properties → Property, etc.)
- Support breadcrumbs navigation in editor
- Enable "Go to Symbol" (Ctrl+Shift+O) quick navigation
- Enable Outline view in sidebar showing scene hierarchy

## Implementation Notes

### Architecture Overview

The implementation will be **lightweight and non-invasive**:

**Components:**
1. **TscnDocumentSymbolProvider** - Single class implementing `DocumentSymbolProvider`
2. **Registration** - Single line in `extension.ts` to register the provider
3. **Parser Integration** - Reuses existing `parseTscn()` from core library

**Data Flow:**

```
.tscn File Opened/Changed
    ↓
VS Code calls provideDocumentSymbols()
    ↓
Parse TSCN using parseTscn()
    ↓
Convert TscnNode tree → DocumentSymbol tree
    ↓
Map node types to SymbolKind
    ↓
Calculate ranges from document text
    ↓
Return symbols to VS Code
    ↓
Displayed in Outline, Breadcrumbs, Go to Symbol
```

### Node Type to SymbolKind Mapping

Map TSCN node types to appropriate VS Code symbol kinds:

```typescript
const NODE_TYPE_TO_SYMBOL_KIND: Record<string, vscode.SymbolKind> = {
  // Mesh nodes → Class (visual representation)
  'MeshInstance3D': vscode.SymbolKind.Class,

  // Camera nodes → Struct (view configuration)
  'Camera3D': vscode.SymbolKind.Struct,

  // Light nodes → Object (illumination)
  'SpotLight3D': vscode.SymbolKind.Object,
  'DirectionalLight3D': vscode.SymbolKind.Object,
  'OmniLight3D': vscode.SymbolKind.Object,

  // Basic spatial nodes → Module
  'Node3D': vscode.SymbolKind.Module,

  // Default fallback → Object
  // All other node types will use Object
};

function getSymbolKind(nodeType: string): vscode.SymbolKind {
  return NODE_TYPE_TO_SYMBOL_KIND[nodeType] ?? vscode.SymbolKind.Object;
}
```

### Range Calculation Strategy

VS Code requires accurate `Range` and `selectionRange` for each symbol:

**Finding Node Definitions:**

TSCN nodes are defined by headings like:
```
[node name="NodeName" type="NodeType" parent="." ...]
```

**Range Strategy:**
1. **selectionRange**: The `[node name="..." ...]` heading line
2. **range**: From heading line to just before next heading (includes all node properties and children)

**Implementation:**

```typescript
function findNodeRange(
  document: vscode.TextDocument,
  nodeName: string,
  parentName: string
): { range: vscode.Range; selectionRange: vscode.Range } {
  const text = document.getText();
  const lines = text.split('\n');

  // Search for node heading
  const pattern = parentName
    ? `[node name="${nodeName}" type=`
    : `[node name="${nodeName}"`;

  let startLine = -1;
  for (let i = 0; i < lines.length; i++) {
    if (lines[i]!.includes(pattern)) {
      startLine = i;
      break;
    }
  }

  if (startLine === -1) {
    // Fallback to first line
    return {
      range: new vscode.Range(0, 0, 0, 0),
      selectionRange: new vscode.Range(0, 0, 0, 0),
    };
  }

  // Selection range is just the heading line
  const selectionRange = new vscode.Range(
    startLine, 0,
    startLine, lines[startLine]!.length
  );

  // Full range extends to next node heading or end of file
  let endLine = lines.length - 1;
  for (let i = startLine + 1; i < lines.length; i++) {
    if (lines[i]!.startsWith('[node ') || lines[i]!.startsWith('[sub_resource')) {
      endLine = i - 1;
      break;
    }
  }

  const range = new vscode.Range(
    startLine, 0,
    endLine, lines[endLine]?.length ?? 0
  );

  return { range, selectionRange };
}
```

### Hierarchical Symbol Conversion

Convert parsed TSCN node tree to DocumentSymbol tree:

```typescript
function convertNodeToSymbol(
  node: TscnNode,
  document: vscode.TextDocument,
  parentName: string = ''
): vscode.DocumentSymbol {
  const { range, selectionRange } = findNodeRange(
    document,
    node.name,
    parentName
  );

  // Create symbol with node name and type
  const symbol = new vscode.DocumentSymbol(
    node.name,                        // Name
    node.type,                        // Detail (shows node type)
    getSymbolKind(node.type),         // Kind
    range,                            // Full range
    selectionRange                    // Selection range
  );

  // Recursively convert children
  if (node.children && node.children.length > 0) {
    symbol.children = node.children.map(child =>
      convertNodeToSymbol(child, document, node.name)
    );
  }

  return symbol;
}
```

### TscnDocumentSymbolProvider Implementation

```typescript
// TscnDocumentSymbolProvider.ts
import * as vscode from 'vscode';
import { parseTscn, type TscnNode } from '@textscene/renderer';

/**
 * Provides document symbols for TSCN files, enabling Outline view and breadcrumbs.
 */
export class TscnDocumentSymbolProvider implements vscode.DocumentSymbolProvider {
  private readonly nodeTypeToSymbolKind: Record<string, vscode.SymbolKind> = {
    'MeshInstance3D': vscode.SymbolKind.Class,
    'Camera3D': vscode.SymbolKind.Struct,
    'SpotLight3D': vscode.SymbolKind.Object,
    'DirectionalLight3D': vscode.SymbolKind.Object,
    'OmniLight3D': vscode.SymbolKind.Object,
    'Node3D': vscode.SymbolKind.Module,
  };

  provideDocumentSymbols(
    document: vscode.TextDocument,
    token: vscode.CancellationToken
  ): vscode.ProviderResult<vscode.DocumentSymbol[]> {
    try {
      // Parse TSCN file
      const parsed = parseTscn(document.getText());

      if (!parsed.nodes || parsed.nodes.length === 0) {
        return [];
      }

      // Convert each root node to DocumentSymbol
      return parsed.nodes.map(node =>
        this.convertNodeToSymbol(node, document, '')
      );
    } catch (error) {
      console.error('Error providing document symbols:', error);
      return [];
    }
  }

  private convertNodeToSymbol(
    node: TscnNode,
    document: vscode.TextDocument,
    parentName: string
  ): vscode.DocumentSymbol {
    const { range, selectionRange } = this.findNodeRange(
      document,
      node.name,
      parentName
    );

    const symbolKind = this.getSymbolKind(node.type);

    const symbol = new vscode.DocumentSymbol(
      node.name,           // Symbol name
      node.type,           // Detail (node type)
      symbolKind,          // Visual kind
      range,               // Full range
      selectionRange       // Selection range
    );

    // Recursively add children
    if (node.children && node.children.length > 0) {
      symbol.children = node.children.map(child =>
        this.convertNodeToSymbol(child, document, node.name)
      );
    }

    return symbol;
  }

  private getSymbolKind(nodeType: string): vscode.SymbolKind {
    return this.nodeTypeToSymbolKind[nodeType] ?? vscode.SymbolKind.Object;
  }

  private findNodeRange(
    document: vscode.TextDocument,
    nodeName: string,
    parentName: string
  ): {
    range: vscode.Range;
    selectionRange: vscode.Range;
  } {
    const text = document.getText();
    const lines = text.split('\n');

    // Build search pattern for node heading
    // Root nodes: [node name="NodeName" type="..."
    // Child nodes: [node name="NodeName" parent="..." type="..."
    let startLine = -1;

    for (let i = 0; i < lines.length; i++) {
      const line = lines[i]!;

      // Check if this is a node heading
      if (!line.startsWith('[node ')) {
        continue;
      }

      // Extract name from heading
      const nameMatch = line.match(/name="([^"]+)"/);
      if (!nameMatch || nameMatch[1] !== nodeName) {
        continue;
      }

      // For child nodes, verify parent matches
      if (parentName) {
        const parentMatch = line.match(/parent="([^"]+)"/);
        if (!parentMatch) {
          continue;
        }

        // Parent "." means direct child of previous node
        // Parent "path" means specific parent
        const parentValue = parentMatch[1];
        if (parentValue !== '.' && !parentValue.includes(parentName)) {
          continue;
        }
      }

      startLine = i;
      break;
    }

    // Fallback if not found
    if (startLine === -1) {
      const fallbackRange = new vscode.Range(0, 0, 0, 0);
      return {
        range: fallbackRange,
        selectionRange: fallbackRange,
      };
    }

    // Selection range is the heading line
    const selectionRange = new vscode.Range(
      startLine,
      0,
      startLine,
      lines[startLine]!.length
    );

    // Full range extends until next node/resource or EOF
    let endLine = lines.length - 1;
    for (let i = startLine + 1; i < lines.length; i++) {
      const line = lines[i]!;
      if (line.startsWith('[node ') ||
          line.startsWith('[sub_resource') ||
          line.startsWith('[ext_resource')) {
        endLine = i - 1;
        break;
      }
    }

    const range = new vscode.Range(
      startLine,
      0,
      endLine,
      lines[endLine]?.length ?? 0
    );

    return { range, selectionRange };
  }
}
```

## Architecture Decision: Why This Approach?

### Rejected Alternative: Native TreeView in Sidebar

We considered implementing a full TreeView in the sidebar (see research summary above) but **rejected it** because:

❌ **Violates Feature Parity Principle**
- Would require maintaining TWO tree implementations
- Web app would still use webview tree
- Duplicate logic for search, selection, expand/collapse

❌ **Violates DRY Principle**
- All tree logic would be duplicated
- Double the maintenance burden
- Risk of feature drift

❌ **Complex Message Passing**
- Tree in extension host, viewport in webview
- Bidirectional sync adds complexity
- Latency in selection synchronization

### Chosen Approach: Lightweight Outline Provider

✅ **Maintains Feature Parity**
- Web app keeps existing webview tree
- VSCode keeps existing webview tree
- Outline provider is VSCode-only bonus feature

✅ **Follows DRY**
- Reuses existing `parseTscn()` parser
- No duplication of tree logic
- Minimal code (~100 lines)

✅ **Simple Architecture**
- No message passing needed
- Provider is stateless
- One-way data flow (document → symbols)

✅ **Complementary, Not Replacement**
- Outline for quick navigation
- Webview tree for rich interactions (search, filters, visibility toggle)
- Both coexist peacefully
