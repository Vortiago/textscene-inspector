# WI-78: Immutable Scene Hierarchies with Reconciliation

**Status**: Not Started
**Priority**: High
**Impact**: Core architectural foundation for multi-panel coordination and efficient scene updates
**Dependency**: WI-76 (Event-Based Resource Loading)

## Overview

### Problem Statement

The current architecture has fundamental limitations:

1. **Model Mutation**: `TscnNode.children` is mutated during external scene loading
2. **No Multi-View**: Each panel has independent `TscnScene` copy
3. **Inefficient Updates**: Destroy-recreate pattern for all changes
4. **No Coordination**: Panels don't know about each other

**Current Flow:**
```typescript
// User edits props/chair.tscn
// Current behavior:
Panel 1: Stale (doesn't know about edit)
Panel 2: Stale (doesn't know about edit)
Panel 3: Stale (doesn't know about edit)

// OR: Manual refresh all panels
updateScene('props/chair.tscn')
  → removeNode(instancePath)  // Destroys 50 THREE.js objects
  → addNode(instancePath)     // Creates 50 new THREE.js objects
  → State lost (animations, gizmos, selection)
```

### Solution: Immutable Hierarchies with Reconciliation

**Pattern Inspiration**: React's Virtual DOM, NOT traditional MVVM/MVC

**Why React's Pattern?**
- ✅ Proven at scale (thousands of components)
- ✅ Simpler than MVVM (no continuous model/view sync)
- ✅ Robust (immutability prevents sync bugs)
- ✅ Easy debugging (clear before/after snapshots)
- ✅ Future features (undo/redo, time-travel debugging)

**Core Principles:**
1. **Immutable State**: SceneGraph never modified after creation
2. **Copy-on-Write**: Updates create new SceneGraph version
3. **Reconciliation**: Diff old vs new, apply minimal changes
4. **Independent Panels**: Each panel reconciles independently (decoupled)

**New Flow:**
```typescript
// User edits props/chair.tscn
File watcher triggers:
  ↓
hierarchyRegistry.updateHierarchy('props/chair.tscn')
  ↓
SceneResolver creates new immutable SceneGraph
  ↓
Registry emits 'hierarchy:updated' event
  ↓
All panels showing 'props/chair.tscn' receive event
  ↓
Each panel: diff(oldGraph, newGraph) → patches
  ↓
Apply patches: Transform-only, Material-only, etc.
  ↓
THREE.js objects preserved (no destroy-recreate)
```

### Core Components

#### 1. SceneGraph (Immutable Data Structure)

```typescript
interface SceneGraph {
  readonly rootScene: string;
  readonly scenes: ReadonlyMap<string, ParsedScene>;
  readonly flattenedNodes: ReadonlyArray<SceneNode>;
  readonly dependencies: DependencyGraph;
  readonly version: number;  // For debugging
}

interface ParsedScene {
  readonly path: string;
  readonly nodes: ReadonlyArray<TscnNode>;
  readonly externalScenes: ReadonlyArray<ExternalSceneRef>;
  readonly resources: ReadonlyArray<Resource>;
}

interface SceneNode {
  readonly path: string;      // Full path (e.g., "Main/Hallway/Door")
  readonly data: TscnNode;    // Original TSCN node data
  readonly source: string;    // Which scene file (e.g., "res://door.tscn")
}
```

**Key Properties:**
- All fields are `readonly` (TypeScript enforces immutability)
- Updates create new SceneGraph (old version unchanged)
- Flattened nodes = single array (easy to diff)

#### 2. SceneGraphBuilder (Copy-on-Write)

```typescript
class SceneGraphBuilder {
  from(graph: SceneGraph): SceneGraphBuilder;
  setRootScene(path: string): SceneGraphBuilder;
  addScene(scene: ParsedScene): SceneGraphBuilder;
  updateScene(path: string, scene: ParsedScene): SceneGraphBuilder;
  removeScene(path: string): SceneGraphBuilder;
  build(): SceneGraph;  // Creates immutable graph
}
```

**Usage:**
```typescript
// Update existing graph
const newGraph = new SceneGraphBuilder()
  .from(oldGraph)
  .updateScene('res://door.tscn', updatedDoorScene)
  .build();
// oldGraph unchanged, newGraph has update
```

#### 3. HierarchyRegistry (Singleton Coordinator)

```typescript
class HierarchyRegistry {
  private hierarchies = new Map<string, SceneGraph>();
  private panels = new Map<string, PanelInfo>();
  private eventBus: ResourceEventBus;  // From WI-76

  async getOrCreateHierarchy(rootScene: string): Promise<SceneGraph>;
  registerPanel(panelId: string, rootScene: string): void;
  unregisterPanel(panelId: string): void;
  async updateHierarchy(rootScene: string): Promise<void>;
}

export const hierarchyRegistry = new HierarchyRegistry();
```

**Responsibilities:**
- Store current SceneGraph per root scene
- Track which panels use which hierarchy
- Emit events when hierarchy updated
- Coordinate scene resolution

#### 4. ReconciliationEngine (Diff + Patch)

```typescript
interface Patch {
  type: 'add' | 'remove' | 'update-transform' | 'update-material' | 'update-visibility';
  nodePath: string;
  data?: any;
}

class ReconciliationEngine {
  diff(oldGraph: SceneGraph, newGraph: SceneGraph): Patch[];
  private diffNodes(oldNodes: SceneNode[], newNodes: SceneNode[]): Patch[];
  private determineUpdateType(old: SceneNode, new: SceneNode): Patch['type'];
}
```

**Algorithm:**
1. Build node maps (path → node) for old and new
2. Find added nodes (in new, not in old) → 'add' patches
3. Find removed nodes (in old, not in new) → 'remove' patches
4. Find updated nodes (in both) → determine minimal update type
5. Return patch list

**This is React's reconciliation algorithm.**

#### 5. Panel Reconciliation Flow

```typescript
class TscnRenderer {
  private currentGraph: SceneGraph | null = null;
  private reconciler = new ReconciliationEngine();

  async loadScene(rootScenePath: string): Promise<void> {
    const graph = await hierarchyRegistry.getOrCreateHierarchy(rootScenePath);

    // Initial render
    this.initialRender(graph);
    this.currentGraph = graph;

    // Subscribe to updates
    hierarchyRegistry.eventBus.on('hierarchy', 'updated',
      (scene, newGraph) => {
        if (scene === rootScenePath) {
          this.reconcile(newGraph);
        }
      }
    );
  }

  private reconcile(newGraph: SceneGraph): void {
    const patches = this.reconciler.diff(this.currentGraph!, newGraph);

    // Apply minimal changes
    patches.forEach(patch => this.applyPatch(patch));

    this.currentGraph = newGraph;
  }
}
```

## Why NOT MVVM/MVC

**MVVM/MVC Problems:**
- Continuous model/view synchronization (complex)
- Observer pattern (tight coupling)
- Two sources of truth (model + view state)
- Synchronization bugs ("model and view disagree")

**Immutable + Reconciliation Advantages:**
- ✅ Simpler: No ViewSynchronizer, no continuous sync
- ✅ Robust: Can't desync (rebuild from source each time)
- ✅ Debuggable: Clear immutable snapshots
- ✅ Proven: React uses this at massive scale
- ✅ Future-proof: Undo/redo, time-travel debugging fall out naturally

**This is the React Virtual DOM pattern, not MVVM.**

## Integration with WI-76

**WI-76 provides**: Event bus for resource and hierarchy events
**WI-78 uses**: Event bus to notify panels of hierarchy updates

**Synergy:**
- WI-76 events trigger resource updates (textures, materials)
- WI-78 events trigger hierarchy updates (scene structure)
- Together: Complete update system

**Example Flow:**
```
User edits door.tscn
  ↓
HierarchyRegistry.updateHierarchy('door.tscn')
  ↓
SceneResolver loads updated scene (uses WI-76 for textures/materials)
  ↓
Build new immutable SceneGraph
  ↓
WI-76 EventBus emits 'hierarchy:updated'
  ↓
Panels reconcile and apply patches
  ↓
WI-76 events handle texture/material updates within reconciliation
```
