### Code Documentation

**JSDoc Comments** - API documentation

Follow these guidelines (from CLAUDE.md):

```typescript
/**
 * One-line description of purpose.
 *
 * @param paramName - Description (if non-obvious)
 * @returns Description (if non-obvious)
 * @throws Error description (if applicable)
 * @example
 * const result = functionName(arg);
 */
export function functionName(paramName: Type): ReturnType {
  // Implementation
}
```

**When to add JSDoc:**
- Public API functions and methods
- Complex or non-obvious functionality
- Functions with multiple parameters requiring explanation
- Functions that throw errors
- Utility functions used across the codebase

**When to skip JSDoc:**
- Simple getters/setters
- Self-explanatory one-liners
- Private implementation details
- Functions where TypeScript types tell the full story

**Inline Comments** - Code explanations

From CLAUDE.md guidelines:

```typescript
// Keep comments for:
// - Complex algorithms (gimbal lock, rotation extraction)
// - Security-related notes (nonce generation, CSP)
// - Non-obvious business logic explanations

// Remove obvious comments:
// ❌ // Initialize variable
// ❌ // Loop through array
// ❌ // Return the result

// Good inline comments:
// Extract Euler angles from rotation matrix (avoids gimbal lock)
const euler = new THREE.Euler().setFromRotationMatrix(matrix, 'XYZ');

// Generate nonce for Content Security Policy
const nonce = crypto.randomBytes(16).toString('base64');
```

### Key Considerations

**1. Documentation Debt**

Avoid accumulating documentation debt:
- Update docs immediately after feature completion
- Don't batch documentation updates
- Treat documentation as part of "done"

**2. KISS Principle**

From CLAUDE.md:
> Minimal documentation: Update docs only when necessary to reduce context overhead

Only document:
- Non-obvious implementation decisions
- Complex algorithms
- Public APIs
- Patterns intended for reuse
- Breaking changes

Skip documenting:
- Obvious code behavior
- Temporary implementation details
- Implementation that may change soon

**3. Consistency**

Maintain consistent style across documentation:
- Use same terminology (e.g., "TSCN" not "tscn file" or ".tscn")
- Follow established section structure
- Use consistent code formatting (triple backticks with language)
- Keep tone professional and concise

**4. Searchability**

Make documentation searchable:
- Use clear section headings
- Include keywords in headings
- Link between related sections
- Use descriptive file names

### ARCHITECTURE.md Update Example

Adding new pattern (Resource Resolution):

```markdown
### Generic Resource Resolution

**Location**: `packages/textscene-renderer/src/resources/resourceResolver.ts`

The resource resolver provides a generic, type-safe pattern for loading any resource type:

```typescript
export async function resolveResource<T>(
  registry: ResourceRegistry,
  resourceId: string,
  typeGuard: (resource: any) => resource is T,
  parser: (resource: TscnSubResource) => ResourceProperties,
  loader: (properties: ResourceProperties) => Promise<T>
): Promise<T>
```

**Benefits:**
- Eliminates code duplication between mesh and material resolution
- Type-safe resource handling
- Consistent error handling
- Extensible to new resource types

**Usage:**
```typescript
const mesh = await resolveResource(
  registry,
  meshId,
  isMeshResource,
  parseMesh,
  loadMesh
);
```

### CLAUDE.md Update Example

Adding new development pattern:

```markdown
### Resource Handler Registration

When creating new resource types, use the self-registration pattern:

```typescript
// packages/textscene-renderer/src/resources/myresource/index.ts
import { resourceRegistry } from '../../core/ResourceRegistry';
import { isMyResource, parseMyResource } from './parser';
import { createMyResource } from './renderer';

resourceRegistry.registerResourceHandler({
  typeName: 'MyResource',
  typeGuard: isMyResource,
  parser: parseMyResource,
  renderer: createMyResource,
});
```

Then import in the main registry file:
```typescript
import './resources/myresource';  // Auto-registers
```
