# WI-60: UV Transform (uv1_scale)

**Status**: Not Started
**Priority**: High
**Estimated Effort**: Small Complexity
**Impact**: 10+ instances in ld-58 for texture tiling

## Overview

### Current State

StandardMaterial3D textures render correctly, but **UV transform properties are not implemented**:
- ✅ Albedo textures render with default UV mapping
- ✅ Normal maps render with default UV mapping
- ❌ `uv1_scale` property is ignored (no texture tiling control)
- ❌ Textures use 1:1 UV mapping regardless of uv1_scale value

### Evidence from ld-58

**Example 1: HallwayGeometry.tscn (line 22)** - Ceiling material with UV scale:
```tscn
[sub_resource type="StandardMaterial3D" id="StandardMaterial3D_tljqy"]
albedo_texture = ExtResource("3_tljqy")
normal_enabled = true
normal_texture = ExtResource("4_lehkh")
uv1_scale = Vector3(0.5, 0.5, 0.5)
```

**Analysis**: `uv1_scale = Vector3(0.5, 0.5, 0.5)` makes the texture repeat twice (0.5 = half size UV coords = double repetitions).

**Example 2: WallSection.tscn (line 28)** - Wood trim with UV scale:
```tscn
[sub_resource type="StandardMaterial3D" id="StandardMaterial3D_06ux7"]
albedo_texture = ExtResource("3_0g1i2")
uv1_scale = Vector3(2.4, 2.4, 2.4)
```

**Analysis**: `uv1_scale = Vector3(2.4, 2.4, 2.4)` makes the texture larger (fewer repetitions).

**Impact**: 10+ instances found in ld-58. Without this, textures stretch incorrectly and lose intended appearance.

**Deferred to v2**: `uv1_triplanar`, `uv1_offset`, `uv2_*` properties

## Implementation Overview

### Parser Changes

Add `uv1_scale` property:

```typescript
export interface StandardMaterial3DProperties {
  // Existing properties...
  albedo_texture?: string;
  normal_texture?: string;

  // NEW: UV transform
  uv1_scale?: THREE.Vector3;
}
```

### Renderer Changes

Apply UV scale to textures:

```typescript
/**
 * Apply UV transform to texture (uv1_scale).
 */
function applyUVTransform(
  texture: THREE.Texture,
  props: StandardMaterial3DProperties
): void {
  if (props.uv1_scale) {
    // In Godot, uv1_scale scales UV coordinates (smaller scale = more repetitions)
    // In THREE.js, texture.repeat scales texture (larger repeat = more repetitions)
    // Formula: THREE.repeat = 1 / Godot.uv1_scale
    texture.repeat.set(
      1 / props.uv1_scale.x,
      1 / props.uv1_scale.y
    );
    texture.wrapS = THREE.RepeatWrapping;
    texture.wrapT = THREE.RepeatWrapping;
    texture.needsUpdate = true;

    logger.info(
      `[StandardMaterial3D] Applied uv1_scale: (${props.uv1_scale.x}, ${props.uv1_scale.y}) -> repeat: (${texture.repeat.x}, ${texture.repeat.y})`
    );
  }
}
```

**Conversion Formula**:
- **Godot**: `uv1_scale = 0.5` scales UV coords by 0.5 → texture repeats twice
- **THREE.js**: `texture.repeat = 2` repeats texture twice
- **Conversion**: `THREE.repeat = 1 / Godot.uv1_scale`

## Linter Requirements

**Validation Rules**:
1. Validate `uv1_scale` format (must be Vector3)
2. Warn if `uv1_scale` has zero components (texture won't render)

```typescript
const uvScaleValidationRule: LintRule = {
  meta: {
    name: 'valid-uv-scale',
    description: 'Validates uv1_scale property on StandardMaterial3D',
  },
  check: (context: LintContext) => {
    // Validate format
    const uv1Scale = subResource.properties.uv1_scale;
    if (uv1Scale && typeof uv1Scale === 'string') {
      const vector3Regex = /^Vector3\(\s*[\d.]+\s*,\s*[\d.]+\s*,\s*[\d.]+\s*\)$/;
      if (!vector3Regex.test(uv1Scale)) {
        // Error: Invalid format
      }

      // Warn if zero components
      const match = uv1Scale.match(/Vector3\(\s*([\d.]+)\s*,\s*([\d.]+)\s*,\s*([\d.]+)\s*\)/);
      if (match) {
        const [, x, y] = match.map(parseFloat);
        if (x === 0 || y === 0) {
          // Warning: Zero component
        }
      }
    }
  },
};
```
