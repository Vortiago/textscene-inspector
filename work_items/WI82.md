# WI-82: Mobile Phone UI Support & Responsive Design

## Overview

Implement comprehensive mobile phone UI support for the web previewer application. This work item adds responsive design patterns, mobile-first navigation with tabbed interface, and touch-friendly interactions to enable TextScene Inspector to work seamlessly on phones, tablets, and desktop devices.

**Current State**:
- CSS foundation with media queries (partially implemented in styles.css)
- Basic HTML structure for tab switching (mobile-tabs in index.html)
- CSS rules for mobile breakpoint (max-width: 767px) with tab-based panel switching
- main.ts ready to handle tab interactions

**Deliverable**:
- Fully functional responsive web app that works at all breakpoints
- Mobile tab navigation for Viewport, Tree, and Controls panels
- Touch-optimized UI with larger buttons and input targets
- Seamless desktop-to-mobile experience

## Architecture Strategy

### Desktop-First Approach

- **Primary Target**: VSCode extension (desktop)
- **Secondary Target**: Web app mobile support
- **Base Styles**: Desktop defaults (3-column grid)
- **Mobile Overrides**: Uses `@layer mobile-overrides` cascade layer (not `!important`)
- **Breakpoints**:
  - Mobile (0-767px): Single column, tab navigation
  - Tablet/Desktop (768px+): 3-column grid (controls, tree, viewport)

### Mobile Navigation Pattern

**Tab-Based Panel Switching**:
- Hidden checkbox inputs: `#panel-viewport`, `#panel-tree`, `#panel-controls`
- Tab bar with 3 buttons: Viewport, Tree, Controls
- CSS `:has()` selector to show/hide panels based on checked state
- No JavaScript required for tab switching (CSS-only implementation)

**Touch Targets**:
- All buttons: Minimum 44×44px (WCAG standard)
- Tree nodes: Larger padding and icons on mobile
- Input fields: Larger text and padding for finger input
- File upload: Full-width with larger touch area

### Responsive Breakpoints Strategy

```css
/* Desktop-first */
@media (max-width: 767px) {
  /* Mobile-specific overrides */
  /* Single column layout */
  /* Show tab navigation */
  /* Hide all panels except selected */
}

@media (min-width: 768px) {
  /* Tablet/Desktop */
  /* Show all panels in 3-column grid */
  /* Hide tab navigation */
}
```

## Implementation Notes

### CSS-Only Tab Switching

The tab switching is implemented entirely in CSS using the `:has()` selector:

```css
/* Show viewport panel when viewport checkbox is checked */
body:has(#panel-viewport:checked) #canvas-container {
  display: block !important;
}

/* Hide other panels when viewport is selected */
body:has(#panel-viewport:checked) #controls {
  display: none !important;
}
```

This approach:
- ✅ No JavaScript required
- ✅ Browser-native state management
- ✅ Instant feedback (no network round-trip)
- ✅ Accessibility built-in (checkboxes are form elements)
- ⚠️ Requires :has() support (modern browsers only)

### Breakpoint Strategy

Mobile-first design but implemented with desktop-first CSS (for clarity):
- Base styles = desktop defaults (3-column grid)
- Media query `@media (max-width: 767px)` overrides for mobile
- Breakpoint at 768px matches industry standards

Alternative would be:
- Base styles = mobile (single-column)
- Media query `@media (min-width: 768px)` for desktop

We chose desktop-first because:
- VSCode extension (desktop) is primary target
- Desktop defaults are clearer in base styles
- Mobile overrides are fewer CSS rules
- Easier to understand override intent

## Known Limitations

1. **CSS :has() Browser Support**
   - Not supported in older browsers (< Chrome 105)
   - Fallback: Page shows desktop layout on unsupported browsers (acceptable)

2. **Touch Event Support**
   - Requires `viewport meta tag` for correct mobile rendering
   - Already present in index.html: `<meta name="viewport" content="width=device-width, initial-scale=1.0">`

3. **Screen Keyboard on Mobile**
   - File input shows native file picker (good)
   - Tree search input will show keyboard (expected)
   - Possible to hide keyboard with `blur()` on mobile if needed
