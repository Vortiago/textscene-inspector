# WI-81: CSS Modernization (Variables, Nesting, Reduce HTML-in-JS)

> Status: largely superseded by the R3F migration's CSS Modules adoption.

## Overview

Modernize the CSS codebase to use contemporary CSS features and patterns, eliminating unnecessary JavaScript-based styling and improving maintainability. This work item establishes **single source of truth for all styles** to solve the core problem: "we have problems with not having control of what CSS ends up controlling the elements."

**Root Problem**: Styles are currently scattered across:
1. CSS files (styles.css)
2. TypeScript inline styles (`element.style.property = value`)
3. TypeScript template strings with embedded HTML/styles

This fragmentation makes it impossible to use CSS linters/formatters on all styling code and prevents IDE autocomplete from working properly.

**Solution**: All presentation values and layout classes defined in CSS files only. TypeScript only touches CSS via `element.style.setProperty('--var', value)` for dynamic values.

**Context**: The project currently has 785 lines of well-structured CSS but uses 30+ hardcoded values, contains 6× `!important` declarations (specificity issues), and has styling logic scattered across TypeScript files. Modern CSS features enable cleaner, more maintainable code with zero backwards compatibility burden (target: newest browsers only).

## Business Value

- **Maintainability**: Single source of truth for all styles (CSS files, not scattered in JS)
- **Consistency**: Themed colors and spacing through CSS variables
- **Tooling**: CSS linters/formatters work on all styling code, IDE autocomplete functional
- **Debugging**: Can search styles.css to find "what makes this button blue?"
- **Developer Experience**: Proper CSS syntax highlighting, easier modifications without risk of regex/template errors
- **Future-proofing**: Established patterns for container queries and advanced CSS features

## Architecture Strategy

**Desktop-First Approach**:
- VSCode extension (desktop) is primary target
- Web app mobile support is secondary priority
- Base styles = desktop defaults
- Mobile overrides use cascade layers (not `!important`)

**CSS-Only Styling**:
- Zero inline `style=""` attributes (except `--custom-properties` for dynamic values)
- Zero HTML template strings with embedded styles
- All styling traceable to styles.css for IDE tooling

### Phase 2: CSS Nesting & Cascade Layers (ENHANCED)

**Goal**: Improve organization with native CSS nesting and eliminate `!important` using cascade layers.

**Desktop-First Strategy**:

The CSS uses a desktop-first approach where base styles target the VSCode extension (desktop layout), and mobile overrides are applied via cascade layers (not `!important`).

```css
/**
 * LAYER STRATEGY (Desktop-First)
 *
 * @layer base          - Desktop defaults (VSCode extension primary)
 * @layer mobile-overrides - Mobile responsive overrides (web app secondary)
 *
 * Layer precedence: Later declared = higher precedence
 * Result: mobile-overrides beats base without !important needed
 */

@layer base, mobile-overrides;

@layer base {
  /* ========== DESKTOP DEFAULTS ========== */
  main {
    grid-template-columns: auto auto 1fr; /* 3-column desktop layout */
  }

  #controls {
    display: block;
    width: var(--panel-controls-width);
  }

  #tree-viewer-panel {
    display: flex;
    width: var(--panel-tree-width);
  }

  #canvas-container {
    display: block;
  }

  /* ========== COMPONENT STYLES WITH NESTING ========== */
  .fixtures-header {
    padding: var(--spacing-md);
    background: var(--bg-input);
    border-bottom: 1px solid var(--border-color);
    cursor: pointer;
    transition: background-color 0.15s;

    &:hover {
      background: var(--color-fixture-header-hover);
    }

    & h3 {
      font-size: var(--text-md);
      font-weight: 600;
      margin: 0;

      &::after {
        content: ' ▶';
      }
    }
  }

  .tree-node-header {
    display: flex;
    align-items: center;
    gap: var(--space-2);
    padding: var(--space-1) var(--space-3);
    cursor: pointer;
    border-radius: var(--border-radius-sm);
    transition: background-color 0.15s;

    &:hover {
      background: var(--color-tree-hover);
    }

    &.selected {
      background: var(--bg-select);

      &:hover {
        background: var(--bg-select-hover);
      }
    }

    &.hidden {
      opacity: 0.5;

      & .tree-node-name {
        color: var(--text-subtle);
        text-decoration: line-through;
      }
    }
  }
}

@layer mobile-overrides {
  /* ========== MOBILE RESPONSIVE OVERRIDES ========== */
  @media (max-width: 767px) {
    /* Hide all panels by default on mobile */
    #controls,
    #tree-viewer-panel,
    #canvas-container {
      display: none; /* No !important needed - cascade layers handle precedence */
      width: 100%;
    }

    /* Single column layout */
    main {
      grid-template-columns: 1fr;
    }

    /* Tab-based panel switching */
    body:has(#panel-viewport:checked) #canvas-container {
      display: block;
      min-height: 400px;
    }

    body:has(#panel-tree:checked) #tree-viewer-panel {
      display: flex;
      min-height: 400px;
    }

    body:has(#panel-controls:checked) #controls {
      display: block;
      max-height: 600px;
      overflow-y: auto;
    }

    /* Touch-friendly sizing */
    .tree-node-header {
      padding: var(--spacing-sm);
      gap: var(--spacing-sm);
    }

    .tree-control-btn {
      padding: var(--spacing-sm) var(--spacing-md);
      font-size: var(--text-md);
    }
  }
}
```

**Why Cascade Layers Eliminate `!important`**:

Layer precedence is determined by declaration order. Styles in `@layer mobile-overrides` automatically override styles in `@layer base` without needing `!important`. This is cleaner than specificity wars.

- Before: `display: none !important;` (mobile has to fight with `!important`)
- After: `display: none;` in higher-precedence layer (automatic override)

**Scope:**
1. Create cascade layers: `@layer base, mobile-overrides`
2. Move all desktop styles into `@layer base`
3. Move mobile media query into `@layer mobile-overrides`
4. Remove 6× `!important` declarations (current lines with `!important`)
5. Apply CSS nesting to 15+ selectors

**Files modified:**
- `apps/textscene-web/styles.css` - Restructure with nesting and layers

**Measurability**:
- Zero `!important` declarations
- All mobile overrides in `@layer mobile-overrides`
- CSS nesting for 15+ selectors
