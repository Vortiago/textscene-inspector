# Float and vector arithmetic

The float types `float`, `vec2`, `vec3` and `vec4`: their literals, the four arithmetic operators, negation, the vector constructors and swizzles. A function of this chapter's instructions translates to TSL nodes that compute what Godot computes, bit for bit, on the GPU that ran the probes.

The GPU sets the edge cases, not the translator. On the probe GPU, an arithmetic operator reads a subnormal input as zero, negation keeps it, and `0.0 / 0.0` is NaN. The tables below show each case as Godot gave it.

Godot 4.6.3-stable (official), probed on llvmpipe (LLVM 20.1.2, 256 bits). Each table shows a sample of a probe's rows, one for each mix of zero, subnormal, normal, infinite and NaN values. The real-GL test (`pnpm test:shaders:gpu`) checks every row, bit for bit. Generated by `pnpm godot:shader-language`: do not edit by hand.

### Float literals

A literal such as `2.5`, `.5`, `1e-3` or `2.5f`. Godot reads the text with its own decimal reader, keeps a 32-bit float, and writes the float back into the GLSL it compiles with 14 decimals (`shader_compiler.cpp:180`). So a value under `1e-14` draws as `0.0`, a value with more digits draws with fewer, and a literal past the float range, such as `1e39`, fails to compile. The translator gives each literal the float that this chain gives.

The translator emits `float(value)`. Rows: `float literal`. Godot source: `servers/rendering/shader_language.h:59`.

### Swizzles

`a.zyx` reads the named lanes, in any order, repeated or not, up to four. The letters come from one set: `xyzw`, `rgba` or `stpq`. Godot refuses a mix such as `a.xg`, and a letter past the vector, such as `.z` on a `vec2`.

The translator emits `a.zyx`. Rows: `vec2.xy`, `vec2.rg`, `vec2.st`, `vec3.xyz`, `vec3.rgb`, `vec3.stp`, `vec4.xyzw`, `vec4.rgba`, `vec4.stpq`. Godot source: `servers/rendering/shader_language.cpp:6877`.
