# Float and vector arithmetic

The float types `float`, `vec2`, `vec3` and `vec4`: their literals, the four arithmetic operators, negation, the vector constructors and swizzles. A function of this chapter's instructions transpiles to TSL nodes that compute what Godot computes, bit for bit, on the GPU that ran the probes.

The GPU sets the edge cases, not the transpiler. On the probe GPU, an arithmetic operator reads a subnormal input as zero, negation keeps it, and `0.0 / 0.0` is NaN. The tables below show each case as Godot gave it.

What to expect: a transpiled function gives Godot's result, bit for bit, except where a GPU driver rewrites inexact float arithmetic. A driver may regroup operations or replace `x + -x` with `0.0`. Godot and the browser hand the driver different code for the same function, so a rewrite can happen on one side only. On the probe GPU, `vec2(a0 - a2) - vec2(0.875, a2)` at `a0 = 16777216.0`, `a2 = 0.5` gives 16777215.0 in Godot. In the browser the driver computes `(a0 - 0.875) - a2`, and the first lane is 16777214.0. The same function on scalars gives the same result on both sides. Most such differences are one unit in the last place. Near infinity, zero and NaN, one side can give NaN where the other gives `-0.0`.

Godot 4.6.3-stable (official), probed on llvmpipe (LLVM 20.1.2, 256 bits). Each table shows at most 8 of a probe's rows, picked to show as many mixes of zero, subnormal, normal, infinite and NaN values as fit. The real-GL test (`pnpm test:shaders:gpu`) checks every row, bit for bit. Generated by `pnpm godot:shader-language`: do not edit by hand.

## Float literals

A literal such as `2.5`, `.5`, `1e-3` or `2.5f`. Godot reads the text with its own decimal reader, keeps a 32-bit float, and writes the float back into the GLSL it compiles with 14 decimals (`shader_compiler.cpp:180`). So a value under `1e-14` draws as `0.0`, a value with more digits draws with fewer, and a literal past the float range, such as `1e39`, fails to compile. The transpiler gives each literal the float that this chain gives.

Arithmetic of literals alone, such as `58.656 + 74.377`, never reaches the GPU as arithmetic. Godot's GLSL compiler, glslang, reads each number of Godot's text as a double, folds the arithmetic in double precision and rounds the result once. The transpiler folds the same arithmetic the same way, so the result can differ by one unit from the same sum in 32-bit floats. Godot also folds a constructor of literals, and a negated literal at the top of an expression, into one constant (`shader_language.cpp:7840`).

The transpiler emits `float(value)`. Rows: `float literal`. Godot source: `servers/rendering/shader_language.h:59`.

## `+` (OP_ADD)

`a + b` adds lane by lane. Two vectors must have the same size. A float on either side applies to every lane of the vector on the other side, and the result has the vector's type.

The transpiler emits `a.add(b)`. ## Negation `-a` (OP_NEGATE)

`-a` flips the sign of each lane, `0.0` and NaN included. When the text Godot writes for `a` already starts with a minus, Godot writes `a` alone (`shader_compiler.cpp:1141`). So `-(-a)` draws as `-a`, `-((-a).y)` as `-a.y` and `-(-1.5) + b` as `-1.5 + b`. The transpiler draws them as Godot does.

## Swizzles

`a.zyx` reads the named lanes, in any order, repeated or not, up to four. The letters come from one set: `xyzw`, `rgba` or `stpq`. Godot refuses a mix such as `a.xg`, and a letter past the vector, such as `.z` on a `vec2`.

The transpiler emits `a.zyx`. Rows: `vec2.xy`, `vec2.rg`, `vec2.st`, `vec3.xyz`, `vec3.rgb`, `vec3.stp`, `vec4.xyzw`, `vec4.rgba`, `vec4.stpq`. Godot source: `servers/rendering/shader_language.cpp:6877`.
