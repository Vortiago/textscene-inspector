# Types and literals

The value types of the shading language, the precision words, and the literals of each scalar type. A value of each type passes through a function and back, bit for bit.

Godot 4.6.3-stable (official), probed on llvmpipe (LLVM 20.1.2, 256 bits). Each table shows at most 8 of a probe's rows, picked to show as many mixes of zero, subnormal, normal, infinite and NaN values as fit. The real-GL test (`pnpm test:shaders:gpu`) checks every row, bit for bit. Generated by `pnpm godot:shader-language`: do not edit by hand.


## Value types

The scalars `bool`, `int`, `uint` and `float`, their vectors of 2 to 4 lanes (`bvec3`, `ivec2`, `uvec4`, `vec3`), and the float matrices `mat2` to `mat4`, stored column by column. An `int` holds 32 bits in two's complement, a `uint` 32 bits without a sign, and a `float` a 32-bit float.

The transpiler emits `int(a), ivec3(a), mat3(a)`. Rows: `bool`, `bvec2`, `bvec3`, `bvec4`, `int`, `ivec2`, `ivec3`, `ivec4`, `uint`, `uvec2`, `uvec3`, `uvec4`, `float`, `vec2`, `vec3`, `vec4`, `mat2`, `mat3`, `mat4`. Godot source: `servers/rendering/shader_language.h:211`.

Every row is native on WebGL 2 and on WebGPURenderer.

## Precision words

`lowp`, `mediump` and `highp` stand before a type. Godot refuses one on a `bool` type. Godot writes the word into its GLSL, and the probe GPU computes every precision in 32 bits, so the result equals `highp`. The transpiler keeps every value in 32 bits.

The transpiler emits `the value with no precision`. Rows: `lowp`, `mediump`, `highp`. Godot source: `servers/rendering/shader_language.cpp:329`.

Lowered rows:

- `lowp`: WebGL 2 lowered: dropped: every float is 32-bit, WebGPURenderer lowered: dropped: every float is 32-bit.
- `mediump`: WebGL 2 lowered: dropped: every float is 32-bit, WebGPURenderer lowered: dropped: every float is 32-bit.
- `highp`: WebGL 2 lowered: dropped: every float is 32-bit, WebGPURenderer lowered: dropped: every float is 32-bit.

## Float literals

A literal such as `2.5`, `.5`, `1e-3` or `2.5f`. Godot reads the text with its own decimal reader, keeps a 32-bit float, and writes the float back into the GLSL it compiles with 14 decimals (`shader_compiler.cpp:180`). So a value under `1e-14` draws as `0.0`, a value with more digits draws with fewer, and a literal past the float range, such as `1e39`, fails to compile. The transpiler gives each literal the float that this chain gives.

Arithmetic of literals alone, such as `58.656 + 74.377`, never reaches the GPU as arithmetic. Godot's GLSL compiler, glslang, reads each number of Godot's text as a double, folds the arithmetic in double precision and rounds the result once. The transpiler folds the same arithmetic the same way, so the result can differ by one unit from the same sum in 32-bit floats. Godot also folds a constructor of literals, and a negated literal at the top of an expression, into one constant (`shader_language.cpp:7840`).

The transpiler emits `float(value)`. Rows: `float literal`. Godot source: `servers/rendering/shader_language.h:59`.

Every row is native on WebGL 2 and on WebGPURenderer.

## Integer literals

A decimal or `0x` literal is an `int`, and with a `u` after it a `uint`. An `int` literal past 2147483647, such as `2147483648`, `99999999999` or `0xffffffff`, is -2147483648 in Godot 4.6.3. A `uint` literal wraps past 4294967295: `4294967296u` is `0u`. A negated literal folds into one constant: `-1u` is 4294967295.

The transpiler emits `int(value), uint(value)`. Rows: `int literal`, `uint literal`. Godot source: `servers/rendering/shader_language.h:60`.

Every row is native on WebGL 2 and on WebGPURenderer.
