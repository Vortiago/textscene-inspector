# Clean Code + STE sweep of docs and code comments

## Context

The docs and code comments carry prose, war stories and history that rot
("three rounds of review found…", "the sweep that removed ~286…", "previously…").
The user's Clean Code and Simplified Technical English (STE) rules say a comment
answers one question in at most four lines, and a document states current fact.
The goal is one PR that brings the prose to those rules and a guard that keeps it
there, because the last one-shot sweep (tracker refs) drifted back within one
merge wave (`packages/textscene-dev-kit/src/commentConventions.test.ts`).

Decided with the user:
- Code: comments and dead code only. No renames, no function extraction.
- ADRs: rewrite to current fact. Keep numbers, filenames, decision, consequences.
- `comparison.md` sheets: tighten cell prose inside the SHEET-STANDARD structure.
- Fan-out: the Workflow tool, several waves, all on branch
  `jolly-coalescing-sunrise`, one PR.

Size: 4,330 source files (466k lines, 114k comment lines), 439 markdown files.

## Keep-list (in every agent brief)

An agent never changes these. Each batch gate checks them mechanically.
- Every engine cite `<file>.(cpp|h|xml):<line>`, in code, comments, cite strings
  and docs. An agent that cannot see the engine source must not add or move one.
- Tool-read comments: `@param @returns @type @ts-* eslint-* # noqa`, JSDoc tags,
  shebangs, frontmatter, licence headers, `GENERATED by`, `keep in sync with …`.
- `describe` / `it` titles: `testTitleTier.guard.test.ts` pins tier words there.
- String literals, error messages, log text, CLI help text.
- ADR numbers and filenames. The duplicate `0032-*` pair is reported, not renamed.
- `CONTEXT.md` terms: `parser/valueDecoderGrammar.contract.test.ts:245` reads it.
- SHEET-STANDARD headings, field keys and table shapes in sheets.
- Any fact. A cut removes narration, history and repetition, never a constraint,
  a contract, a number with its reason or a "why not the other choice".

## What an agent cuts or rewrites

Per the two rule files (`Verktoykasse/main/clean-code/clean-code-rules.md`,
`…/simplified-technical-english/ste-rules.md`), in short:
- War stories, review rounds, "previously", dates, PR narration, counts that rot
  ("~2,000 files", "237 leaf validators") unless a test asserts the number.
- Comments longer than four lines: keep the question it answers, move nothing to
  docs unless the fact exists nowhere else.
- Comments that repeat the name or the code; section rules of dashes.
- Dead code and commented-out code (proven unused by grep, and by
  `noUnusedLocals` where typechecked).
- STE surface: em dashes, semicolons between sentences, contractions, Latin
  abbreviations, `via`, praise words, future tense for behaviour, British spelling,
  sentence ≤25 words, paragraph ≤6 sentences, capitals used for emphasis.

## Wave 0: tooling (as built)

- `packages/textscene-dev-kit/src/proseRules.ts` (+ test): the mechanical rules
  (em dash, contraction, Latin abbreviation, `via`, comment over four prose
  lines), comment blocks for code and `.tscn`, and markdown prose extraction.
- `.sweep/proseConventions.test.ts.pending`: the guard. It stays here while it
  is red, because a red test fails the commit and push hooks. The last step
  moves it to `packages/textscene-dev-kit/src/proseConventions.test.ts`.
- `.sweep/scan.mjs`: per-file findings. `.sweep/worklist.mjs` wrote the frozen
  `.sweep/batches.json` (54 batches, waves 1 to 8).
- `.sweep/check.mjs <files>`: guard findings for files. `.sweep/commentOnly.mjs`
  and `.sweep/keepList.mjs [files]`: the two diff gates against the base.
  All read the built dev-kit, so run `pnpm --filter @textscene/dev-kit build`
  after a change to `proseRules.ts`.
- `.sweep/BRIEF.md`: the editor brief every agent follows.

## Waves (Workflow, agents edit this worktree on disjoint paths, no agent commits)

One Workflow run per wave, over the batches of that wave in `batches.json`.
Each batch is a pipeline of two agents: an editor that follows `BRIEF.md`, then
a verifier with a fresh context that reads the batch diff against the base,
restores any lost fact and fixes what the editor left. Agents never commit,
because the pre-commit hook restores its stash over concurrent edits.

- Wave 1: prose documents that later agents read (6 batches).
- Wave 2: ADRs (2 batches) and parity sheets (5 batches).
- Waves 3 to 8: code comments and `.tscn` fixture comments, about 3,000 comment
  lines per batch, 8 batches per wave.
- Last: whatever the guard still lists, then move the guard in.


## Resumability

A usage stop can end the session mid-wave. Everything a new session needs lives
in the branch, never in the scratchpad (it is session-specific) or in a Workflow
run (`resumeFromRunId` works in the same session only).

- **Durable state in the repo.** Wave 0 commits `.sweep/`: `plan.md` (this
  file), the three scripts, and `batches.json` (batch id, wave, exact file list,
  base sha `9a495d2a`). Frozen once written: a resumed run uses the same
  partition. The final commit deletes `.sweep/`.
- **The ledger is git.** Each batch lands as its own commit with the trailer
  `Sweep-Batch: <id>`. A batch is done if and only if
  `git log --grep '^Sweep-Batch: <id>$'` finds it. Nothing else records progress.
- **Commit after the wave, one commit per batch.** No agent edits while a
  commit hook runs, so the session commits each batch in turn once every agent
  of the wave has stopped. Push after every wave, so a removed worktree or a
  lost machine loses at most one wave.
- **Idempotent batches.** The rules applied to text that already follows them
  change nothing, so rerunning an editor on a half-edited file is safe. A resume
  never discards edits with `git checkout`.
- **Resume procedure** (a new session in this worktree, told "resume the sweep"):
  1. Read `.sweep/plan.md` and `.sweep/batches.json`.
  2. List done batches from the trailers, and dirty files with `git status`.
  3. For each started batch (dirty files, no trailer), rerun its editor on its
     own file list, then gate and commit it.
  4. Start a Workflow for the remaining batches of the current wave, then
     continue with the next waves.
- **Same session**: when the Workflow run itself stopped, stop it with
  `TaskStop`, then rerun with `resumeFromRunId` so finished agents return from
  cache.
- **Memory note at wave 0**: a project memory `sweep-in-progress` that points to
  `.sweep/plan.md` and the resume procedure, deleted at shipping.

## Per-wave gate (session runs, in order)

1. `node .sweep/commentOnly.mjs` and `node .sweep/keepList.mjs`: zero unexplained
   diffs. `node .sweep/check.mjs <wave files>`: zero findings, or each one listed
   as unplaced by its agent.
2. `npx eslint <changed files>`.
3. `pnpm type-check:all` and `pnpm type-check:tests`.
4. `pnpm test:unit` with a large timeout (background, never piped).
5. Sheets wave: `test:unit` includes `scripts/compare-docs/*.test.mjs`
   (`sheets.test.mjs`, `parseSections.test.mjs`), so check them by name in its log.
   After any change to a sheet or `docs/comparison/README.md`, run
   `pnpm docs:index` and `pnpm docs:gallery` and commit `docs/comparison/`:
   the index rows and the gallery's shared notes are generated from them.
6. Fixture wave: `pnpm build:linter && pnpm lint:tscn <files>`, `pnpm lint:scenes`.
7. Commit each batch: `docs: …` / `refactor: …`, conventional, with the
   `Sweep-Batch: <id>` trailer. Then push the branch in the background.

## Shipping

1. Before wave 1, create one GitHub issue for the sweep from this plan.
2. Final gate: the whole `validate` script, `proseConventions.test.ts` green.
3. Push in the background, verify with `git ls-remote`
   (`[[push-hook-exceeds-tool-timeout]]`).
4. Open one PR from `jolly-coalescing-sunrise` to `main`, body ends
   `Closes #<n>`.
5. Delete `.sweep/` in the last commit. Replace the `sweep-in-progress` memory
   with one that names the guard and says the prose rules are enforced.

## Verification

- `proseConventions.test.ts` green over all scanned comments and docs, with its
  printed coverage count equal to the comment span count.
- `commentOnly.mjs` shows only listed dead-code removals across the whole branch
  diff against `9a495d2a`.
- `keepList.mjs` shows zero lost engine cites, tags, directives and test titles
  over the branch diff.
- `validate` green; no golden, e2e or CSP gate is needed because no runtime
  code changes, and `commentOnly.mjs` proves that.
- Spot read: 20 random changed files per wave by the session, for lost facts.

Start `.sweep/wave.workflow.txt` with the Workflow tool (`scriptPath`), with
